# Contributing to CodeCabinate

Thank you for your interest in contributing to **CodeCabinate**.

CodeCabinate is a proprietary project. Contributions are welcome, but the project and its source code remain subject to the **CodeCabinate Proprietary Software License**.

## How to Contribute

### 1. Fork the Repository

Create a fork of the official CodeCabinate repository on GitHub.

### 2. Create a Branch

Create a separate branch for your changes.

Example:

```bash
git checkout -b feature/add-search
```

Use descriptive branch names such as:

* `feature/...` — for new features
* `fix/...` — for bug fixes
* `docs/...` — for documentation changes
* `refactor/...` — for code refactoring

### 3. Make Your Changes

Make your changes while following the project's coding standards and conventions.

Please ensure that:

* Your code is readable and maintainable.
* Your changes are focused and relevant.
* Existing functionality is not unnecessarily broken.
* Sensitive information such as passwords, API keys, access tokens, and secrets is not committed.
* You do not include unnecessary or unrelated changes.

### 4. Test Your Changes

Before submitting a Pull Request, test your changes locally.

Where applicable:

* Add new tests for new functionality.
* Update existing tests when behavior changes.
* Ensure that existing functionality continues to work.
* Verify that your changes do not introduce new errors.

### 5. Commit Your Changes

Use clear and descriptive commit messages.

Example:

```text
Add profile avatar upload
```

Avoid vague commit messages such as:

```text
update
changes
fix
```

### 6. Submit a Pull Request

Open a Pull Request against the appropriate branch of the official CodeCabinate repository.

Your Pull Request should explain:

* What you changed.
* Why you made the change.
* How you tested the change.
* Any limitations or known issues.

### 7. Code Review

All Pull Requests are reviewed by the CodeCabinate project maintainers.

A Pull Request may be:

* Accepted and merged.
* Returned with a request for changes.
* Rejected.

Submitting a Pull Request does not guarantee that the contribution will be accepted or merged.

## Third-Party Code

Do not submit code copied from another project unless you have verified that its license permits the intended use.

When submitting third-party code:

* Ensure that its license is compatible with the CodeCabinate project.
* Clearly identify the third-party code when required.
* Preserve required copyright notices and license information.
* Include applicable third-party license information when required.

Contributors are responsible for ensuring that their contributions do not knowingly violate the intellectual property rights or licenses of others.

## Security Issues

Do not report security vulnerabilities through public GitHub Issues.

Please follow the instructions provided in `SECURITY.md` for responsibly reporting security vulnerabilities.

## Questions

For questions about contributing to CodeCabinate, open a GitHub Discussion or contact the project maintainers through the official project channels.

Thank you for helping improve CodeCabinate.
